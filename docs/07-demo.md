# 07. 데모 시나리오 (팀원 3 정리, 전원 확인)

> 발표 때는 "시선 추적"이 아니라 **"얼굴이 보이는지(정면인지)로 재생/정지"**라고 설명한다.
> 눈만 휴대폰으로 내리면 얼굴은 정면이라 계속 재생된다. 질문이 나오면 이 한계를 그대로 말한다.

## 1. 30분 전 준비

| # | 할 일 | 확인 방법 | 담당 |
|---|---|---|---|
| 1 | 노트북을 휴대폰 핫스팟(2.4GHz)에 연결 | 학교 Wi-Fi는 기기 간 통신이 막혀 있을 수 있음 ([02 §4](02-containers.md#4-네트워크-체크리스트-집-공유기-기준)) | 전원 |
| 2 | 노트북 IP 확인 → 펌웨어 `config.h`의 `FP_MQTT_HOST`, 업로드 | `ipconfig`의 IPv4 | 팀원 2 |
| 3 | `.env`의 `MQTT_WS_URL` — 같은 노트북 브라우저면 `ws://localhost:9001` 그대로 | | 팀원 3 |
| 4 | `docker compose up -d --build` | `docker compose ps`에서 broker `healthy` | 팀원 3 |
| 5 | 메시지 확인 창을 하나 띄워 둔다 | `docker exec -it fp-broker mosquitto_sub -v -t 'facepause/#'`에 xiao-01 `online` | 팀원 3 |
| 6 | http://localhost:8080 → 장치 `xiao-01` → 데모 영상 불러오기 → **시작하기** 클릭 | 배지가 "자리 비움"/"시청 중"으로 바뀜, HUD 숫자 갱신 | 팀원 3 |
| 7 | 데모 영상이 임베드 허용인지 | "외부 재생이 허용되지 않습니다"가 뜨면 다른 영상으로 (최근 영상 목록에 예비 1~2개) | 팀원 3 |
| 8 | 보드 위치·조명 | 카메라 앞 **약 0.5m**(1m에서는 검출 안 됨), 얼굴을 **화면 가운데**에, 정면, 역광(창문 등지기) 피하기 ([05 §5](05-face-model.md)) | 팀원 1 |
| 9 | 비상용 sim 준비 | `docker compose --profile sim up -d --build sim` (장치 `sim-01`, 평소에는 선택 안 함) | 팀원 3 |

## 2. 시연 순서 (약 5분)

[04 §5](04-team-plan.md#5-통합-체크리스트-300-600)의 T1~T7을 보여 주는 순서다. 말하는 사람과 앉는 사람을 미리 정한다.

| 순서 | 동작 | 화면에서 보여 줄 것 | 대략 시간 |
|---|---|---|---|
| 1 | 구조 설명: 보드가 얼굴을 직접 검출, 영상은 보드 밖으로 안 나감 | [01 아키텍처](01-architecture.md) 그림 한 장 | 40초 |
| 2 | (T1) 카메라 정면 약 0.5m에 앉는다 | 1초 안에 재생, 배지 "👀 시청 중", HUD `faces 1`·`fps` 약 5 | 20초 |
| 3 | (T3) 고개를 옆으로 돌린다 | 약 2초 뒤 정지, "⏸ 자리 비움". 돌아보면 다시 재생 | 30초 |
| 4 | (T4) 손으로 0.5초 얼굴을 가린다 | **계속 재생** — 디바운스 설명 (2프레임 / 1.5초) | 20초 |
| 5 | (T2) 자리를 떠났다 돌아온다 | 정지 → 재생, 재생 위치가 그대로 | 30초 |
| 6 | (T5, 선택) 두 사람이 같이 본다 | HUD `faces 2` — 0.5m 거리·가운데 정사각형 안에 두 얼굴이 다 들어와야 해서 리허설에서 안 되면 뺀다 | 20초 |
| 7 | (T6) 보드 USB를 뽑는다 | **15~22초 뒤** "⚠ 장치 오프라인" + 정지 — 기다리는 동안 LWT 설명 | 40초 |
| 8 | USB를 다시 꽂는다 | 부팅·Wi-Fi·MQTT 접속 후 "장치" 점 초록, 앉아 있으면 다시 재생 | 40초 |
| 9 | (T7) 브라우저 새로 고침 → 시작하기 | 현재 상태가 바로 반영 (retained) | 20초 |

## 3. 막혔을 때

| 증상 | 바로 할 일 |
|---|---|
| 보드가 브로커에 안 붙음 (배지 "연결 대기", 장치 점 회색) | 장치를 `sim-01`로 바꾸고 아래 sim 키로 같은 순서를 시연. 원인(IP, 방화벽, 2.4GHz)은 발표 뒤에 |
| 얼굴을 잘 못 잡음 | 0.5m까지 다가가 얼굴을 화면 가운데에, 조명 켜기. 그래도 안 되면 sim으로 |
| 영상이 재생되지 않음, 오버레이가 다시 뜸 | 브라우저 자동 재생이 막힌 것 → **시작하기** 다시 클릭 |
| "⚠ 브로커 연결 끊김" | `docker compose ps` → broker 재시작. 웹은 2초마다 알아서 다시 붙는다 |
| 영상이 계속 멈췄다 켜졌다 함 | **얼굴 제어** 토글 OFF → 일반 플레이어로 계속 진행 |
| "⚠ 센서 응답 없음" | 3초 넘게 센서 결과가 안 온 것 (정상 부팅은 약 1.4초에 첫 결과). 보드 리셋. 결과가 다시 오면 배지는 저절로 돌아온다 |
| "⚠ 카메라 오류" | 카메라 초기화 실패 → 보드 리셋, 카메라 커넥터 확인 |
| 인터넷이 끊김 | 유튜브와 mqtt.js(unpkg)를 인터넷에서 받으므로 핫스팟 데이터 확인 |

### sim으로 대신 시연하기

`.env`에 `SIM_SCENARIO=interactive`를 넣고 sim을 다시 띄운 뒤 붙는다.

```bash
docker compose --profile sim up -d --build sim
docker attach fp-sim          # 빠져나올 때는 Ctrl+P, Ctrl+Q (Ctrl+C 는 sim 종료)
```

| 키 | 보드에서의 의미 | 웹 결과 |
|---|---|---|
| `p` | 얼굴이 보임 | 재생 |
| `a` | 얼굴이 사라짐 | 정지 |
| `e` | 센서 멈춤 (`sensor_timeout`) | 정지 + "⚠ 센서 응답 없음" |
| `o` | 센서 복구 (`online`) | 배지 원래대로 |
| `d` | 전원 뽑힘 (LWT) | 바로 "⚠ 장치 오프라인" |
| `r` | 다시 접속 | 복구, 얼굴 있으면 재생 |

자동으로 돌리고 싶으면 `SIM_SCENARIO`를 `cycle`(5초마다 전환), `sensor`(센서 오류→복구 반복), `offline`(LWT→재접속 반복) 중 하나로.
